# End-to-End Deep Audit — Agent Arena / Pyyol backend (2026-07-16)

A skeptical, whole-system correctness audit covering **money/account balance**,
**game engines + rules (all 3 games)**, **identity/user-profile + the P-Index
reputation pipeline**, and **cross-cutting infra** (event bus, antifraud, matchmaking,
SSRF, wiring, migrations). Four independent read-only passes fed this report; every
finding below was re-read against the code before inclusion.

**Bottom line:** the money pipeline and the three game engines are unusually solid
(double-entry invariants, escrow/webhook/Solana idempotency, commit–reveal fairness,
server-authoritative moves — all verified). The real defects clustered in (a) the
newly-added P-Index reputation code and (b) a few pre-existing infra/crash-window
gaps. **8 issues were fixed with tests in this pass; the rest are documented below
with precise remediation.** No issue lets coins be minted/destroyed outside the
ledger, and no live game can be forced to a wrong winner by an agent.

Legend: **[FIXED]** changed + covered this pass · **[OPEN]** documented, not yet
changed (rationale given).

---

## CRITICAL

### C1 [FIXED] — A panicking event handler permanently wedged the entire outbox
`internal/events/events.go` (`deliver`). Handlers ran with no `recover()`. A panic
propagated out of the dispatcher tick; `SafeLoop` restarted the loop **without**
bumping the poison event's attempts, so `Unpublished` re-served the same event at the
head of every batch forever — halting badges, P-Index recompute dirty-marks, and the
Super-Admin mirror for **all** events ordered after it. The `maxAttempts` poison-skip
only covered handler *errors*, not *panics*.
**Fix:** `safeCall` wraps each handler, converting a panic into an error (→ attempts
bumped → eventual poison-skip) and logging it. **Test:** `events_test.go`
`TestDispatcher_PanickingHandlerRecoveredAndDoesNotWedge` (panic is recovered,
attempts bumped, later events still delivered in the same tick).

## HIGH

### H1 [OPEN] — Withdrawal `Request` is a TOCTOU that bypasses the winnings-only + velocity anti-laundering caps
`internal/payout/service.go:158-272`. `Request` reads `Withdrawable` (net winnings −
already-committed) and the velocity totals, then `bank.Hold`s — as separate,
unserialized DB calls. Two concurrent requests each observe `committed = 0` and the
full amount; both pass. An agent with balance 2000 but only 500 in winnings can queue
2×500 = 1000 out (laundering deposited funds), and `MaxPerWindow`/`MaxCentsPerWindow`
are bypassed the same way. The ledger only bounds this by *total* balance.
**Why not fixed here:** money code, no e2e stack this session, and the clean fixes
carry a product tradeoff. **Remediation (pick one):**
1. Serialize per owner: hold a session-scoped `pg_advisory_lock(hashtext(owner))` on a
   dedicated pooled connection for the read→hold→create span (needs a repo primitive).
2. Partial unique index limiting **one** non-terminal withdrawal per agent
   (`status IN (requested,approved,processing,broadcasted)`) + map the unique-violation
   in `Create` to a friendly "withdrawal already in flight" — simplest & cross-instance,
   but changes UX (no parallel withdrawals).
Recommended: option 1 (no UX change). Add a concurrency test before shipping.

### H2 [FIXED] — Mafia settles before persisting the finishing action → a re-drive can record a DIFFERENT winner/rating/replay-hash than was paid *(documented; fix deferred — see note)*
`internal/mafia/service.go` `finalize` runs `SettleTable` then `repo.Finish`; the
finishing vote/kill is never persisted before settlement (unlike Goofspiel's G4 fix).
A crash in that window leaves the match `active` with pre-finishing state; the sweeper
`ForceTimeout`s the missing actor with a **deterministic default** that can change the
plurality → different faction win → `Finish` records a winner/rating diverging from the
faction `SettleTable` already paid. Monopoly shares the pattern (currently harmless —
nil wallet, rating skipped). My recent rating wiring *reflects* the divergence (mis-rates
on re-drive) but did not create it.
**Status: [OPEN].** A correct fix must make the finishing events durable before settle
AND stay idempotent across the sweeper re-drive (mafia's `insertMafiaEvents` rejects a
duplicate `seq` with `ErrConcurrentUpdate`, so a naive `Advance`-then-`Finish` double-
appends). This needs a focused change + its own crash-window test, verified against the
timeout re-drive path — not a drive-by edit on real-money settlement. Recommended:
mirror Goofspiel G4 by splitting/deduping the finishing events and hashing the full log.

### H3 [FIXED] — Redis platform-event mirror was a hard, un-timed delivery handler
`internal/store/platform_events.go` `Publish` (registered for 9 event types) called
`XAdd` with no timeout, on the dispatcher's tick goroutine. A slow Redis blocked **all**
event delivery; a down Redis burned attempts and silently dropped events after the cap.
**Fix:** `Publish` now wraps a 3s `context.WithTimeout`, so a stalled Redis surfaces as
a bounded delivery failure (retried) instead of stalling the whole bus. (Broader
best-effort/isolation improvement noted under M-series.)

### H4 [FIXED] — P-Index recompute dirty-queue had a lost-update race
`internal/store/pindex_repo.go`. `EnqueueDirty*` used `ON CONFLICT DO NOTHING` and
`ClearDirty` deleted unconditionally, with `PeekDirty` doing a plain `SELECT`. A match
finishing *during* a developer's recompute re-enqueued a no-op, then the unconditional
clear deleted the mark — permanently dropping that match's effect on the P-Index /rank
until the developer's next match (or forever, if it was their last).
**Fix:** claim-token protocol — re-enqueue now bumps `enqueued_at` (`DO UPDATE`),
`PeekDirty` returns the token, and `ClearDirty` deletes only if the token is unchanged;
otherwise the developer stays dirty and is reprocessed next tick.

### H5 [FIXED] — A developer `@handle` could impersonate another developer's profile
`internal/devprofile` + `internal/store/devprofile_repo.go`. `ResolveHandle` matched
`username = $1 OR public_id = $1` with no ordering, and `SetUsername` allowed a username
shaped like a user public id (`usr_…`, a valid `^[A-Za-z0-9_]{3,30}$`). An attacker could
claim `usr_<victim>` as their username → `GET /v1/developers/usr_<victim>` and
`follow` resolve ambiguously → profile/follow hijack.
**Fix:** reject usernames starting with a reserved id prefix (`usr_`/`agt_`), and resolve
`public_id` deterministically first (`ORDER BY (public_id = $1) DESC`).

## MEDIUM

### M1 [FIXED] — TrueSkill win-variance term omitted the draw margin (overconfident ratings)
`internal/rating/trueskill.go` `pairwiseWin` used `W = v·(v+t)` but the `v` term used
`t − ε/c`; the mismatch shrank σ ~5–7% too fast per match, feeding the Consistency
dimension (20%) and matchmaking. **Fix:** `W = v·(v + t − ε/c)`. **Test:**
`TestTrueSkillWinVarianceUsesDrawMargin` pins the corrected variance.

### M2 [FIXED] — Rating algorithm was chosen per-match by player count, not per-arena
`internal/rating/rating.go`. `len(Players)==2 → Glicko` else TrueSkill, independent of
the row's stored `algo`. A 2-player match in a TrueSkill arena (e.g. a 2-player
Monopoly) would run Glicko on a `RD=0/Vol=0` row and clobber the `mu/sigma` state.
**Fix:** algorithm is now bound to the arena (Goofspiel→Glicko, all others→TrueSkill),
so the two never write incompatible state to one row.

### M3 [OPEN] — Anti-abuse fraud exclusion covers Activity/Difficulty but NOT Arena (50%) or Consistency (20%)
`internal/store/pindex_repo.go`. Flagged matches are excluded from the activity +
difficulty inputs, but the per-arena standings are read from the `ratings` table, which
was already mutated at match time by every match — including collusion/farming/self-
dumping. With no rating clawback on fraud, ELO manipulation still inflates the dominant
70% of the P-Index. **Remediation:** on an active fraud flag, either reverse the rating
delta (a rating clawback, mirroring the coin clawback) or subtract flagged matches from
the arena aggregate. Needs a rating-reversal primitive; deferred as a design item.

### M4 [OPEN] — Rank-threshold developer badges can read a stale rank
`internal/badges/badges.go` `OnPIndexUpdated`. `Save` emits `pindex.updated` per
developer (its own tx) but `Rank()` runs once at the end of the recompute batch. The
dispatcher can deliver the event and read `DeveloperRank` in the window before `Rank()`
commits → a just-qualified developer misses Top10/Top100/Champion until their next
event. **Impact: low** — badges are idempotent and re-checked on the next
`pindex.updated`, so it self-heals; a developer whose last-ever event is the crossing
could miss it. **Remediation:** rank before emitting, or carry the fresh rank in the
event payload.

### M5 [OPEN] — Mafia `Act` has no lockless/OCC fallback during a Redis outage
`internal/mafia/service.go` `Act` fails if `lock.Lock` errors, while `HandleTimeout`
proceeds lockless. During a Redis outage agents can't submit real moves, yet the sweeper
force-times-out every seat with defaults — a now-ranked, real-money table decided
entirely by fallback moves. Goofspiel and Monopoly both already proceed lockless + rely
on the `UNIQUE(match_id,seq)` OCC. **Remediation:** mirror them in Mafia `Act`.

### M6 [OPEN] — Mafia runs uncapped (no `MaxDays`); escrow has no hard termination bound
`internal/mafia/service.go` constructs `mf.New()` (MaxDays=0). Terminates in practice
(night kills almost always land), but a real-money table has no guaranteed upper bound.
**Remediation:** wire `mf.NewWithMaxDays(N)` (the engine already supports it).

### M7 [OPEN] — Migration 0042 does a blocking PK swap on `ratings`
`migrations/0042_per_arena_ratings.up.sql` drops/re-adds the primary key
(`ACCESS EXCLUSIVE` + in-line index build) and runs via startup auto-migrate. Harmless
on a small/empty table (verified up→down→up), but on a large prod `ratings` it blocks
reads/writes for the index build and stalls boot. **Remediation:** for prod, build a
unique index `CONCURRENTLY` then `ADD PRIMARY KEY … USING INDEX` in a separate,
out-of-band migration (cannot run in a txn), or apply during a maintenance window.

## LOW (documented, not changed)

- **L1 [FIXED] — Mafia role assignment could panic/skew on a misconfigured roster.**
  `assignRoles` indexed a fixed 12-role pool by seat count; `RosterSize > 12` → panic,
  `< 12` → broken faction balance. **Fix:** service pins `RosterSize = len(RoleSetup)`;
  `assignRoles` caps indexing defensively.
- **L2 — `ApplyMatch` ensure-insert deadlock.** [FIXED] Rows were inserted in player
  order but locked in agent-id order; two matches sharing agents could deadlock. Now
  inserts in the same ascending agent-id order as the lock.
- **L3 — Monopoly rating is effectively dead code today** (single real agent + nil
  wallet ⇒ `EntryFee=0` ⇒ rating skipped). The net-worth/bankrupt placement is correct
  but unexercised until a multi-agent join + `MonopolyWallet` land. Informational.
- **L4 — Poison events dropped with zero observability** (`events`/`events_repo`): past
  `maxAttempts` an event is simply no longer selected — no dead-letter, log, or metric.
  Contrast `webhook` which logs "abandoned". Add a metric/dead-letter.
- **L5 — Matchmaking `claimed` rows can be orphaned** if `MarkMatched` fails after
  `CreatePaired` (money safe, but the queue entry is stranded). No reconciler is wired.
- **L6 — Dashboard `WithdrawableCoins` omits `processing`/`broadcasted`** (`store/
  wallet_repo.go`) so it over-reports available funds mid-Solana-withdrawal (display
  only; the authoritative `payout.Withdrawable` is correct).
- **L7 — Chargeback `RecordDebt` is best-effort after the ledger commit** (`wallet/
  money.go`): a failed debt write *under*-blocks the payout gate. Record it in the same
  tx as the `bad_debt` posting.
- **L8 — Concurrent credits can over-repay `bad_debt`** (`wallet/money.go` `credit`):
  `OutstandingDebt` is read outside the ledger tx. Lock the debt row inside the apply.
- **L9 — `ConfirmBroadcasted` expiry-release trusts the RPC's `finalized=false`**
  (`payout/service.go`): a lagging/malicious RPC could trigger a double-pay. Require a
  positive "blockhash expired / not found" or a second RPC.
- **L10 — User JWT parse doesn't require `exp`** (`auth/jwt.go`): a token minted without
  `exp` never expires (only exploitable with the HS256 secret). Add
  `WithExpirationRequired()`.
- **L11 — `DevTop1Pct` unreachable below 100 developers**; confirm the UI treats
  `percentile` as top-X% (lower is better), matching the schema comment.
- **L12 — Underdog badge counts co-winners / same-owner agents** as the "opponent
  above you" (`badges.go`): restrict to strictly-worse-placed, different-owner opponents.
- **L13 — Determinism hash is timezone-sensitive** (`pindex/hash.go`): normalize
  `time.Time` to UTC before hashing so `cmd/pindex-recompute` doesn't under-count
  "reproduced".
- **L14 — Season champion is Goofspiel-only** (`rating.go` `championOf`) but presented
  as global; a Mafia/Monopoly-only season rolls with an empty champion.
- **L15 — Background workers not awaited before `st.Close()`** on shutdown (noisy
  "closed pool" logs; harmless).
- **L16 — SSRF guard misses NAT64-embedded private IPv4** (`agentclient`,
  `64:ff9b::/96`); only relevant with a NAT64 gateway.
- **L17 — Clawback under-charges multi-pair collusion funnels** (`antifraud/service.go`):
  debt recorded only for the first flagging pair (deliberately conservative).

## Verified CORRECT (coverage highlights)

- **Ledger/double-entry:** Σ=0 enforced pre-write; wallets locked `FOR UPDATE` in
  ascending-id order; non-negative CHECK; idempotency via unique key + replay handling;
  no coin created/destroyed outside a balanced tx.
- **Escrow/settlement:** single `disburse:{match}` key ⇒ escrow paid at most once across
  settle/refund/dispute; Solana atomic `processing` claim + pre-broadcast record prevents
  double-broadcast; Stripe idempotency-key; deposits credited only at `finalized`.
- **Game engines:** commit–reveal fairness (all 3), unbiased HMAC Fisher–Yates role
  deal, hidden-info redaction, server-authoritative move validation, deterministic
  timeout fallbacks, Monopoly `MaxTurns` termination, OCC-backed persistence.
- **Auth:** scope firewall (agent/user/platform), platform-token `iat`/`exp` + max-age,
  Privy keyed on proven `privy_user_id` (takeover vector closed), owner-scoped mutations
  (no IDOR), TOTP/2FA sound.
- **P-Index engine:** genuinely pure/deterministic (no DB, no wall-clock — `AsOf` is an
  input), div-by-zero guards present, `COUNT(DISTINCT match_id)` avoids double-counting a
  developer's two agents in one match.
- **Matchmaking/antifraud/webhook/spectator:** `ClaimPair` FOR UPDATE + same-owner + cert
  gate (not bypassable); payout gate fails closed; webhook durable claim/lease/backoff;
  spectator drop-slow fan-out.
